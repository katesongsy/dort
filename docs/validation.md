# Validation methods and test isolation

[Documentation](README.md) · [Architecture](../ARCHITECTURE.md) · [Contributor instructions](../AGENTS.md)

This is a maintained technical reference for the test infrastructure, not a release checklist, implementation plan or record of a particular candidate's results. Test counts, run IDs, temporary evidence and unfinished milestone gates belong in ignored planning notes and local artifacts. A passing earlier revision is not evidence for a changed working tree.

## Ordinary checks

From the repository root, with the pinned Rust toolchain and Python 3:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked -- --nocapture
cargo build --workspace --locked
python3 scripts/check-docs.py --self-test
python3 scripts/check-docs.py
python3 scripts/test-terminal.py
git diff --check
```

The Python scripts use only the standard library. Ordinary checks do not install tools, mount volumes, fill disks or operate on real dotfiles. Cargo may fetch locked dependencies/toolchain components as needed. [CI](../.github/workflows/ci.yml) runs the ordinary gates on Ubuntu x86_64/ARM64 and macOS Intel/Apple Silicon, records platform/tool versions and requires a non-root user plus distinct Linux cross-device fixture filesystems. A configured matrix is not proof that a particular run passed.

The [documentation checker](../scripts/check-docs.py) scans maintained root Markdown and `docs/` recursively, including `docs/user/`. It validates inline local links/fragments, ignores fenced examples and rejects links to ignored specifications. It is not a general Markdown parser or external-URL checker. Keep its self-tests aligned with the documentation layout.

## Fixture and external-tool boundaries

- Use disposable canonical HOME/config/state/repository roots and explicit core `HostContext` inputs. macOS `/var` aliases need their physical path spelling.
- Never change process-global HOME/XDG in Rust tests; set isolated child environments instead. Never automate destructive real-home smoke tests or provider/package-manager execution on a workstation.
- CLI tests use deterministic fake/missing Git fixtures. Optional core real-Git tests use disposable repositories and announce missing-Git skips; examine those messages rather than treating skips as exercised coverage.
- Permission-denial tests cannot establish refusal when run as root. Linux cross-device tests need a genuinely distinct device, not a second directory on the same filesystem; unavailable fixtures must be reported explicitly.
- Ordinary reports/events/logs must remain metadata-only. Do not retain file bodies, local variable values, credentials or raw terminal buffers in evidence. Explicit escaped Git patch reports and the ephemeral selected-file Discover pane are separate bounded content exceptions; neither belongs in validation artifacts.

## Coverage and interpretation

| Area | Suites / boundary |
| --- | --- |
| Manifest/profiles/planning | Core unit/integration tests verify strict parsing, dependency/selection rules, deterministic pure plans, unsupported effects and no-op behavior. |
| Filesystem observation | [Observation](../crates/dort-core/tests/observation.rs) tests no-follow parents/terminal entries, unsafe paths, unreadable files, special files, hard links, bounds and sensitivity heuristics. Linux additionally permits real non-UTF-8/FIFO fixtures. |
| File lifecycle | [Adoption](../crates/dort-core/tests/adoption.rs) and [lifecycle](../crates/dort-core/tests/lifecycle.rs) exercise fresh approvals, backup failures/corruption, immutable intent, forward/inverse interruption, stale/edit/parent guards, source preservation, separate removal acknowledgement and repeated apply. |
| Bootstrap/recovery | [Bootstrap](../crates/dort-core/tests/bootstrap.rs) and [recovery](../crates/dort-core/tests/recovery.rs) cover schema dispatch, staged publication/registration, explicit head-bound recovery, malformed tails and refusal to overwrite edits or delete published repositories. |
| Concurrency | [Separate-process lock tests](../crates/dort-core/tests/state_process.rs), crash suites and CLI fixtures verify one writer and OS lock release. Other editors are not coordinated by the app lock. |
| Git | [Git integration](../crates/dort-core/tests/git.rs) and runner/parser tests cover unusual/unborn/conflict/worktree cases, helper/filter refusal, output/deadline bounds, explicit disclosure/escaping and unchanged input bytes/identities. |
| CLI/TUI | Command tests, pure application/view snapshots, [TUI workflows](../crates/dort/src/tui/tests/workflow.rs) and the PTY gate cover approval, dry-run, cancellation, small layouts, guarded services and terminal/worker ownership. |

Application parity tests compare shared CLI/TUI requests, reports and plans. Sequential filesystem observations are not globally atomic; plan comparisons normalize only volatile parent-directory size/timestamps/link counts, matching the core approval digest, while retaining parent identity/mode/ownership and all file observations. Fixture siblings can otherwise cause nondeterministic comparison failures. Pure state/view tests also cover profile contributions/reset, independent scopes, retained drafts, compact focused controls, raw selection identity, full-scope apply despite filters and exact-ID lifecycle forms. TUI parser errors must not disclose manifest source excerpts. Recovery tests cover all-repository search with global blockers outside the filter, selected full IDs across refresh, schema/phase/integrity action hints, independent history despite bad configuration, explicit bootstrap resume/abandon retaining published artifacts and fresh-preview/confirmation after lock failure. Diagnostics tests compare the shared doctor metadata and distinguish unknown configuration from zero registrations without disclosing source excerpts; About reports the build version and preserves destination. Deterministic [Git TUI fixtures](../crates/dort/src/tui/tests/git.rs) compare typed metadata with the same backend, exercise independent roots/missing Git/refusals/empty comparisons and verify that patches require the one-view phrase, never prefetch or enter generic diagnostics, and are dropped on close/shrink/navigation/exit. Discovery workflow fixtures verify ineligible directory rows are labeled, Enter preserves retained drafts without creating state, and eligible regular-file rows still open editable drafts. Compact tests keep the warning/input visible at 48×14. Text-only assertions verify all destination/selection/mode labels without relying on color at 48×14, 80×24 and wide sizes. Long-list fixtures exercise selected mapping/repository/transaction visibility and unfiltered Recovery blockers, retained drafts through shrink/grow and form-back, while real core previews exercise escaped metadata scroll bounds and Home reset without authorizing writes. Direct-key/mouse fixtures cover independent metadata scrolling without raw row changes, Discover pane-focus Tab and otherwise local/inert Tab, direct destination keys, hovered list/details wheels, filtered raw identity, actual table offsets, stale geometry refusal and compact inspect/back after resize. Local form controls retain Tab navigation; mouse cannot submit filled exact-ID/yes inputs or disclosure phrases. Cell-level workbench fixtures also check active-tab/selection styles, accented border colors, real input caret position and field/button visibility across compact, baseline and wide terminals. Typed file-review fixtures verify that selecting a mapping does not alter the original plan/scope and that the complete report remains available without enabling dry-run approval. These automated checks are not evidence that an unfamiliar user can discover or understand every workflow.

[Selected-batch core tests](../crates/dort-core/tests/batch.rs) exercise all four schema-4 actions, exact selected subsets, combined conflict/approval bounds, every exposed forward/inverse error and process-exit boundary, write blocking, explicit restartable whole-transaction recovery, corrupt tails/backups and independent rejection of a rehashed but altered scope. Older schema fixtures retain their independent scope/format coverage. [Batch TUI tests](../crates/dort/src/tui/tests/batch.rs) use real keys/cells/mouse at the floor for tree folds/marks, hidden selections, retained per-file drafts, combined previews, every exact deletion ID then yes, shrink reset, disabled/dry-run paths and unchanged full-scope semantics.

[Discover fixtures](../crates/dort/src/tui/tests/discover.rs) exercise passive selected-file reads without activity panels, selection-generation late-result drops, escaping, sensitive/stale refusal, preview-only/shrink/navigation withholding, dominant content geometry, prominent ineligible marking and retained list offsets with mouse identity. Core observation fixtures cover depth-eight hidden directories, nested plugins, authentication/session exclusions, scans exceeding the former entry limit, bounded selected-content reads and content-free discovery serialization. Small-budget core unit fixtures independently exercise per-directory and shared recursive exhaustion without creating oversized directory trees. Batch adoption fixtures verify a combined editable default table, no per-file acceptance loop, one real-preview Adopt all activation and return to refreshed Discover with current managed/history observations and retained receipt metadata. Other write/deletion and Git disclosure guards remain independent.

[Adoption-default fixtures](../crates/dort/src/tui/tests/adoption_defaults.rs) compare single/batch HOME-relative suggestions across disposable home roots, retain editable drafts and distinguish common basenames. Core batch failure-boundary/process-exit fixtures also retain an existing array-of-tables mapping with a nested override through append and recovery; focused regressions cover absent/empty/inline file declarations, byte-for-byte compatibility of previously successful append output, and exact original-byte rollback. Batch fixtures execute nested-source adoption without relocating existing mappings and verify exclusive compact/wide rendering without background Files row formatting. PTY coverage checks the covered editor and preserved repository paths through adoption/rollback. Item-form regressions cover list selection, literal text, Enter/Done/Esc retention, exclusive compact/wide rendering and mouse return to combined review without individual approval. Discover fixtures cover keyboard/mouse focus, wrapped-row page/end metrics, unchanged file selection/marks, no reread on focus changes, compact visibility and text/modal/Git/floor/dry-run isolation.

[Core ignore fixtures](../crates/dort-core/tests/discovery_ignore.rs), [TUI ignore fixtures](../crates/dort/src/tui/tests/ignore.rs) and CLI discovery tests cover persistent exact-component exclusions/new descendants, confirmed undo, stale/cross-host approval refusal, private bounded malformed/link rejection, content withholding and no-write preview/dry-run/small-layout behavior. Fixtures never access real HOME.

[Responsiveness fixtures](../crates/dort/src/tui/tests/responsiveness.rs) inject up to 100,000 synthetic candidate records without creating or reading corresponding files. They exercise passive preparation on the owned worker, search/help/quit during preparation, superseded query/scope rejection, queued explicit-task ownership, default-closed folders, immediate fold/mark retention without a new task, cached snapshot identity through folding/navigation/resize, raw mouse identities and viewport-bounded row formatting. [Navigation fixtures](../crates/dort/src/tui/tests/navigation.rs) check Vim chords/page capacity, text-entry isolation and timestamp-driven double-click marking, including coalesced clicks and keyboard/resize invalidation. The visibility index has pure nested-range/rank tests. These deterministic assertions do not establish a wall-clock latency guarantee or substitute for physical-terminal review.

[Context catalog/Actions fixtures](../crates/dort/src/tui/tests/palette.rs) check unique commands and appropriate workflow reachability across destinations, separate scope/effect labels, retained unavailable reasons and typed search dispatch. [Help fixtures](../crates/dort/src/tui/tests/help.rs) check F1 and non-text ?, literal text, independent scroll, exact retained drafts/query/focus, exclusive rendering and non-submission across views, forms, batches, pickers, task/error/completion surfaces. Real ignore/batch/Git fixtures additionally preserve opaque previews, confirmation input and deletion acknowledgements across Help, enforce shrink reset, and withhold private/late content. Ignore controls have real key/mouse coverage at compact, baseline and wide sizes with confirmed undo. These checks do not constitute unfamiliar-user or physical-terminal review.

[Task-surface fixtures](../crates/dort/src/tui/tests/task_surface.rs) exercise real compact keys/cells/mouse for immutable activity scope across destination changes, metadata-only boundary/sequence updates, joined-quit feedback, full wrapped paths/transaction IDs, pinned failure risk, retained read-intent retry, write-failure refresh/Recovery and completion/no-op receipts through refresh and Back. Result controls are also rendered at baseline/wide sizes. PTY checks exercise actual approved/no-op completion panels and clicked controls; a disposable held writer lock verifies failed-write feedback offers read-only refresh without changing history. Existing worker-join, source-excerpt suppression and private-patch non-disclosure tests remain independent.

Process exits at persisted boundaries demonstrate process-crash handling, not power-loss durability. Callback errors, permission failures and exclusive-create collisions do not substitute for real ENOSPC. Checksummed intent and guards detect corruption/edits; they do not isolate a malicious same-user/root process or make multi-path operations globally atomic.

[Appearance fixtures](../crates/dort/src/tui/tests/appearance.rs) assert ASCII-only cells, terminal-default monochrome colors, retained reverse/bold selection, visible textual states and unchanged caret/hit geometry at compact, baseline and wide sizes. Pure capability tests cover locale precedence and independent character/color choices without process-global environment mutation. Real removal previews retain exact-ID/yes, mouse non-submission and shrink-reset guards in ASCII/monochrome mode. Synthetic light/dark default foreground/background and black/cyan ANSI contrast calculations state their palette assumptions; they do not establish readability on a customized palette or real terminal/font. Physical light/dark/low-color terminal review and unfamiliar-user acceptance require separate observation.

## Real terminal checks

[The PTY gate](../scripts/test-terminal.py) discovers fresh executable paths from Cargo JSON and runs isolated fixtures without an installed-Git requirement. It checks terminal/default entry, q/Ctrl-C, compact low-color navigation and Home help reset without state, F1 over Actions/real previews/confirmation with retained text and non-submission, visible compact ignore/undo controls with shrink-reset approval, explicit path Review/Select button activation, candidate inspection followed by a separate visible adoption action, preapproval cancellation, dry-run refusal, retained text drafts/missing Git, nonpersistent repository selection, guided create/attach, repository-independent discovery/adoption, retained manual adoption, independent standalone manifest/profile checks, display-only file search/full-scope previews, independent Git root/status/diff/search and explicit one-view patch disclosure with no prefetch or refresh fetch, exact-ID link deletion, approved apply, searchable history/full IDs and guarded rollback without hash transcription, read-only Diagnostics/About and normal/error/panic restoration. Dedicated batch sessions cover fold-retained discovery marks, editable combined adoption and schema-4 rollback, selected Apply with hidden marks, Keep, and Delete with every ID and shrink-reset acknowledgements. Each approval is checked against the expected single schema-4 transaction and untouched unselected files/sources. Bootstrap fixtures inject a deterministic fake Git rather than requiring an installed executable. A supervisor retains the controlling terminal long enough to compare attributes; only the kernel PENDIN retype flag is ignored. Wait/output capture is bounded and owned fixture children are cleaned up on failure; raw screen buffers are not printed. Files/Recovery/Git sessions also send SGR mouse clicks/wheel events, exercise direct keys, Home, Discover list/content focus with wrapped Vim scrolling, local form Tab and actual PTY resize without unintended content disclosure or new writes. Normal/error/panic exits assert that every enabled mouse-reporting mode is disabled again. A small bounded VT view interprets cursor-addressed differential draws for text assertions (including split escapes/UTF-8); it is not a general terminal emulator. Raw bytes are retained only within each disposable session for terminal-restoration assertions.

Appearance PTY fixtures pass explicit child-only TERM/locale/NO_COLOR environments to the binary, avoiding Python supervisor locale coercion. They independently check ASCII vs Unicode output, absence/presence of explicit color SGR, real tab clicks and form text/Tab input, no state creation and clean restoration. The bounded VT view and synthetic palettes are not evidence of physical terminal/theme/font review.

The terminal-session failure/panic probe exists only in isolated test children, not as a production fault switch. Preserve the approved finish-writes-before-exit policy: preapproval cancel does nothing, an approved write is never detached/cooperatively stopped/automatically undone, and errors restore the terminal and join the owned worker. Forced termination cannot promise cleanup.

## Opt-in bounded storage checks

[The storage launcher](../scripts/test-storage-vm.py) is **not an ordinary CI or workstation check**. Every mounted-volume/fault environment needs separate explicit approval and independent isolation review. Never fill a host disk, mount host data into a fault guest or reuse unrelated VMs/containers.

The current launcher is restricted to a non-root Linux user in the reviewed guest named `lima-a12`, an administrator-owned `/run/dort-approved-storage-vm` marker containing `dort-isolated-lima-a12-v1` plus LF (mode 0644), and no detected virtiofs/9p/SSHFS shares. The marker is an administrative guard, **not proof of isolation**; never create it on a workstation. It does not provision or create a VM.

Only inside a separately approved, verified disposable guest:

```sh
python3 scripts/test-storage-vm.py --approved-disposable-vm
```

The launcher builds the normally ignored Linux-only [Rust storage probe](../crates/dort-core/tests/storage_faults.rs) before mounting. It allocates a bounded 128 MiB ext4 image with 4 KiB blocks, no reserved-space percentage and delayed allocation disabled. It verifies the exact loop backing file, mount and distinct device; all fixture HOME/config/state/repository/destination paths live on that filesystem. No production fault-injection API or cross-device fallback is added.

The probe tests allocation, preparation, first durable intent, first mutation and nonempty partial-checkpoint exhaustion for adoption/apply/keep/remove and schema-3 attachment. It requires actual kernel errno 28, checks earlier checkpoint hashes and watched sources, and verifies unchanged live input identities before publication. The partial-record case reclaims only two blocks of its own filler after verifying a successful baseline checkpoint exceeds that space. Controlled geometry and reclamation are important: metadata/allocation headroom makes a single freed block unreliable for producing a nonempty partial write.

After freeing only harness-owned filler, valid preparation must recover explicitly; malformed immutable tails must refuse recovery and continue blocking new writers. Never delete/truncate journals to enable recovery. The launcher owns/reaps its process group before cleanup, unmounts without lazy/force fallback and removes only its temporary scope; failed unmount retains the scope for diagnosis. Stop the dedicated guest after use and retain reviewed metadata-only evidence separately.

This establishes only the failures actually observed on the tested revision/filesystem. It does not establish every operation boundary, new-repository Git preparation/publication, inverse ENOSPC, failing fsync, other-platform cross-device handling or real power-loss safety. Preserve those distinctions in any candidate-specific evidence record.
