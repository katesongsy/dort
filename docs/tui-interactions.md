# Workbench interaction contracts

The [design system](design-system.md) is the mandatory visual/component standard for new or changed surfaces; it is not a claim that every legacy screen already conforms. The workbench separates navigation surfaces from approval ownership. End-user keys and workflows are documented in the [command reference](user/commands.md#interactive-interface).

## Pages and dialogs

Workflow forms, batch editing, reviews, results, errors, history and ignored-path management are navigable pages. `surface.rs` provides page titles, breadcrumbs and Back. The render-owned Places mouse target remains available while editing text; Ctrl-K provides keyboard access to searchable destinations and tasks. Left/Right never changes destinations. Opening/dismissing a menu preserves fields, focus and opaque previews; selecting an available destination, including the same tab, drops pending approvals and private Git payload references but retains drafts.

Short repository/profile choices, Actions, Help/About and existing final confirmation/disclosure gates are framed, dimmed dialogs. Only the foreground owns hit regions and input caret. Background clicks and navigation attempts explain the paused navigation; they never implicitly cancel, approve or disclose content. Esc and explicit Close/Cancel controls leave the dialog. A running worker also pauses navigation, with visible feedback; q/Ctrl-C waits for the one owned joined worker.

## Direct actions and metadata

Tab/Shift-Tab traverses actual form fields, never footer actions. Enter requests the primary validation/review from any field, focusing a genuinely missing field when needed. Secondary actions use explicit nonprinting shortcuts or typed click targets; ordinary printable shortcut letters remain text in fields. Full form metadata uses F3 and scrollable readers; Enter there never submits a hidden form. Shared action bars wrap controls independently of field focus.

Choice and inventory lists traverse rows only. Space toggles optional selections; Enter invokes the contextual primary action from any row. Profile Enter validates/applies additions, while Space or checkbox clicks toggle optional names. Repository Ctrl-N opens Create/attach. Picker/Actions F3 opens scrollable full metadata; Esc returns to choices. Enter in metadata cannot activate hidden rows. Actions Esc closes directly, including from search.

Inspect installed tools defaults to four manager rows. Space toggles eligible real query previews; Enter consumes the selected previews once. `e` opens Advanced for the selected row, `r` refreshes suggestions without querying, and F3 shows exact scopes. Advanced and declaration Enter prepare a read-only review; only the subsequent existing gate can execute a provider or write a declaration.

Batch adoption separates list selection from the three-field item form. List Enter reviews the complete marked set; `e` edits one item. Item Enter/Done or Esc retains edits and returns to the list, never requesting an individual preview. F3 exposes full selected-item paths.

Files, Recovery and Git Enter opens a full reading page at every width; reader arrows and paging scroll metadata, never hidden list rows. Esc returns to the retained list. Discover Enter remains inspection, not adoption; Recovery Enter remains inspection. Git patch content still requires its separate deliberate warning and explicit disclosure action. Approval, dry-run, layout-floor, shrink, freshness, source identity, unresolved-attempt and joined-worker contracts remain in the core services and existing frontend gates; navigation hints do not grant authority.

Provider inventory browsing uses the shared one-line filter and aligned package/version table under one location header and source summary. One foreground action strip owns direct Details/Done, More and Help actions; the obsolete search-title and extra status/toolbar hints are withheld on this surface. A retained failed-write/possible-partial-effects warning remains visible as an inline risk notice; simplifying chrome must not discard it. F2 opens contextual More, whose explicit choices retain ordinary query/preview boundaries. Esc/outside-click guards, retained filter/draft focus and row identities stay independent of approval; full program scope remains in Details. Places opens destination choices even on wide inventory layouts. The same shell and foreground action strip apply to every workflow. F3 opens full metadata; F4 opens explicit provider choices or optional declaration dependencies where offered. Ctrl-K opens the global searchable task launcher. Places is groups-first at every width, with a persistent destination rail on wide layouts.

## Text and validation

The single foreground action strip shows up to eight contextual entries, fitting the available width; F2 More appears only when additional eligible actions do not fit. The same partition governs keyboard and mouse access to More. The strip follows the actual foreground: Help overrides retained pages/menus/tasks/errors; declaration and Advanced pages describe field/review actions rather than browsing shortcuts. Metadata subviews advertise scrolling and explicit Back controls, never hidden row selections or inert Enter actions. Reconciliation distinguishes tool-row traversal, an explicit snapshot-choice dialog and the direct Enter comparison; selecting a binding never queries a provider. These controls describe existing dispatch and grant no execution authority.

Trusted Unicode decoration is distinct from metadata. `StatusText` escapes owned dynamic ingress; trusted static/count chrome is explicit. Metadata still escapes non-ASCII, control and bidi characters at boundaries. There is no global unescape. Terminal-cell clipping preserves UTF-8 and existing independent ASCII/color fallbacks.

State/backend tests cover row/field traversal, single-use real previews, draft retention versus actual navigation, dialog dimming/hit capture, foreground caret ownership, compact action availability and malicious metadata. Disposable-fixture PTY journeys supplement these assertions. Automated rendering and terminal tests do not establish unfamiliar-user intuitiveness; see [validation limits](validation.md).
